# Инструменты

Сервер даёт агенту 55 инструментов. Агент сам выбирает нужный по описанию, которое сервер
передаёт ему на английском; здесь — что делает каждый, по-русски. Если модель не
указана, инструмент работает с активной моделью ЛИРЫ. Единицы — текущие единицы ЛИРЫ
(их показывает `lira_model_summary`).

Где инструмент читает или правит узлы и элементы (правка, чтение таблиц узлов и
элементов, чтение нагрузок, результаты), вместо номеров можно написать `selected` — то, что инженер
выделил мышкой в окне ЛИРЫ, — или `visible` — то, что ЛИРА показывает, например после
фрагментации. Модель должна быть открыта в ЛИРЕ; после расчёта ЛИРА её закрывает, так
что для результатов её открывают снова. Выделение пользователя сервер не меняет.
Замена нагрузок и запись таблиц принимают только номера: их агент берёт из ответа
чтения, чтобы правка попала ровно в прочитанное.

Если версия ЛИРЫ не умеет то, что нужно инструменту, он отвечает понятной ошибкой, а
`lira_status` перечисляет такие инструменты.

## Состояние и модели

| Инструмент | Что делает |
|---|---|
| `lira_status` | Найденные версии ЛИРЫ, какая используется, подключена ли; возможности API этой версии и инструменты, которые она не выполнит. ЛИРУ не запускает |
| `lira_list_models` | Открытые в ЛИРЕ модели: имя, путь, тип, есть ли несохранённые изменения, какая активна |
| `lira_open_model` | Открыть файл `.lir` (запускает ЛИРУ, если нужно) |
| `lira_create_model` | Создать пустую модель заданного типа |
| `lira_save_model` | Сохранить модель, в том числе под новым именем; перед сохранением убирает временные таблицы сервера |
| `lira_close_model` | Закрыть модель |
| `lira_model_summary` | Сводка: тип схемы, единицы, число узлов и элементов, типы КЭ, жёсткости, загружения, есть ли результаты |
| `lira_model_picture` | Картинка модели в PNG — как её рисует ЛИРА |

## Выделение

| Инструмент | Что делает |
|---|---|
| `lira_selection` | Какие элементы и узлы инженер выделил в окне ЛИРЫ (`selected`) или видны на экране (`visible`, после фрагментации — только фрагмент): номера диапазонами и их число. Агент показывает число пользователю до правки |
| `lira_find_elements` | Элементы по признакам из слов инженера: типы КЭ, жёсткости, отметка Z или диапазон отметок (все узлы элемента в нём), вид, этаж и марка конструктивного блока, материал конструирования; можно искать внутри выделенного или видимого. Ответ — номера диапазонами, число по типам КЭ и жёсткостям, диапазон Z |

## Резервные копии

| Инструмент | Что делает |
|---|---|
| `lira_list_backups` | Копии модели, которые сервер сделал перед первой правкой |
| `lira_restore_backup` | Вернуть копию на место модели (текущий файл тоже сохраняется копией) |

## Таблицы ввода и текстовый формат

| Инструмент | Что делает |
|---|---|
| `lira_list_input_tables` | Таблицы ввода, которые поддерживает эта версия ЛИРЫ |
| `lira_read_table` | Строки таблицы ввода (все или по номерам) |
| `lira_write_table` | Записать строки в таблицу ввода и применить к модели; ошибки ЛИРЫ возвращаются по строкам |
| `lira_export_text` | Вся модель в текстовом формате ЛИРЫ |
| `lira_import_text_model` | Создать модель из текстового формата и сохранить в `.lir` |
| `lira_read_loads` | Нагрузки модели (из текстовой выгрузки); можно только на указанных элементах и узлах |
| `lira_set_loads` | Заменить нагрузки сохранённой модели — всех или указанных загружений, а с `elements` / `nodes` — только на этих элементах и узлах (остальные нагрузки не трогаются, агенту не нужно передавать миллион нагрузок модели). Сервер пересобирает модель из текста (со стадиями монтажа), возвращает все таблицы ввода, сверяет таблицы, нагрузки и полный текст модели и только потом перезаписывает файл. Если сверка не прошла (например, нормы сочетаний не по умолчанию — не СП 20.13330, а СНиП; потерянные данные нелинейного расчёта), исходная модель не меняется, а пересобранная сохраняется рядом черновиком `<имя>_кор_нагр_error.lir` с отчётом `<имя>_кор_нагр_error.txt` о различиях; нужен ли он, решает пользователь. Перед каждой правкой — свежая резервная копия. Неупакованную схему (удалённые узлы и элементы с сохранёнными номерами) сервер не правит: агент спрашивает пользователя, и с `pack=true` сервер только упаковывает и сохраняет схему (только удалённые узлы и элементы; номера меняются), не применяя нагрузки; агент заново читает нагрузки и присылает их в новой нумерации. Большая модель (230 тыс. узлов) правится около 20 мин |

Справочник столбцов таблиц, кодов типов КЭ и текстового формата агент читает как ресурс
`lira://reference/tables`.

| Инструмент | Что делает |
|---|---|
| `lira_add_nodes` | Добавить узлы по координатам |
| `lira_add_elements` | Добавить элементы одного типа КЭ по узлам, с жёсткостью |

| `lira_self_weight` | Добавить собственный вес в загружение (или удалить его) |

## Расчёт

| Инструмент | Что делает |
|---|---|
| `lira_run_analysis` | Запустить расчёт сохранённой модели и дождаться его (или вернуться сразу) |
| `lira_analysis_status` | Состояние последнего расчёта: идёт, закончен, с ошибкой, остановлен |
| `lira_stop_analysis` | Остановить расчёт |
| `lira_analysis_protocol` | Протокол решателя с предупреждениями |
| `lira_punching_check` | Проверка продавливания посчитанной модели — как пункт меню ЛИРЫ «Расчет арматуры > Расчет продавливания»: нагрузки на контуры продавливания и арматура продавливания. Расчёт её не выполняет — запускать после каждого расчёта: нагрузки от проверки, сделанной до последнего расчёта, ЛИРА не удаляет, и сервер отказывается их отдавать как устаревшие |
| `lira_delete_results` | Удалить результаты расчёта модели |

## Результаты

Сервер не отдаёт таблицы целиком: он возвращает экстремумы и N наибольших строк, а
полную таблицу по запросу пишет в CSV или Excel. Есть отбор по порогу и огибающие по
загружениям. Общие аргументы запроса (`components`, `sort_by`, `top`, `threshold`,
`envelope`, `export_path`) описаны один раз в ресурсе `lira://reference/query`; в описании
каждого инструмента — только строка со ссылкой на него.

| Инструмент | Что делает |
|---|---|
| `lira_node_displacements` | Перемещения узлов по загружениям (для динамики — по формам и суммарные, `shape: "sum"`) |
| `lira_element_forces` | Усилия и напряжения элементов всех типов КЭ по загружениям (для динамики — по формам и суммарные, `shape: "sum"`) |
| `lira_load_combinations` | Список РСН модели: номер, имя, формула, особое, сейсмическое |
| `lira_combination_displacements` | Перемещения узлов в РСН |
| `lira_combination_forces` | Усилия и напряжения в РСН по предельным состояниям |
| `lira_design_forces` | РСУ: сочетания, критерии, группы, состав загружений |
| `lira_periods` | Периоды, частоты, модальные массы и коэффициенты участия форм |
| `lira_reinforcement` | Подобранная арматура железобетонных элементов |
| `lira_fragment_loads` | Нагрузки на фрагмент (для динамики — по формам и суммарные, `shape: "sum"`) |
| `lira_punching_loads` | Нагрузки на контуры продавливания по узлам контуров (для динамики — по формам и суммарные); появляются после `lira_punching_check` |

## Плиты

Сервер сам читает сетку и результаты и считает плиты по правилам, согласованным с
владельцем ([продукт](PRODUCT.md), «Вторая версия»); агент получает короткую сводку по
каждой плите. Плита — связная часть изгибаемых пластин и оболочек на одной отметке; её
опоры — узлы, которые держит что-то снизу: колонны и стены, уходящие вниз, связи по Z,
одноузловые опоры и сваи, АЖТ (все степени свободы) и объединения перемещений по Z с
таким узлом.

| Инструмент | Что делает |
|---|---|
| `lira_slab_deflections` | Прогиб плит по линиям между опорами, по загружению или РСН. Предел прогиба по нормам РК задаётся для проекта (СП РК EN 1993-1-1, п. 7.2.1; НП.2.21): `deflection_limit` = N для l/N; без него — только факты: f, пролёт и L/f (`L_to_f`), вывод «предел не задан». По каждой плите худшая линия — точка на ней, прогиб, пролёт (длина линии), опоры; с пределом — допустимый прогиб и вывод; ещё два опасных участка и все участки с превышением (`other_spans`, в ответе первые 10), наинизшая точка каждой панели (`panel_lows`, первые 5), наибольшее по абсолютной величине перемещение со своим знаком. У плиты на одноузловых упругих элементах и у плиты с коэффициентами постели — осадка со знаком ЛИРЫ и относительная разность осадок между конструкциями на плите; пределы — по СП РК 5.01-102-2013, прил. В, табл. В.1 через `structure` (`rc_frame` 0,002 и 100 мм, `rc_frame_tied` 0,003 и 150, `steel_frame` 0,004 и 150, `steel_frame_tied` 0,005 и 180, `no_uneven_forces` 0,006) или заданные `settlement_limit_mm` и `relative_settlement_limit`; без них — только факты. С `output_dir` — отчёт Word и PDF (`report`: `both`, `docx`, `pdf`, `none`) с изополями прогиба (изополе отношения к пределу — только когда предел задан); PNG — с `pictures=true`, DXF — с `dxf=true`. `elements` ограничивает отчёт выбранными плитами (номера, `selected`, `visible`) |
| `lira_cracked_copy` | Копия сохранённой модели с учётом трещин в плитах: коэффициент kE к модулю упругости (0 < kE ≤ 1, задаёт инженер) всем пластинам плит или указанным элементам, в таблицу `Stiffnesses_Factors` копии `<модель>_kE<коэф.>.lir` (точка — подчёркиванием: kE 0,5 → `_kE0_5`; ЛИРА не принимает `. # * ? ,` в имени модели). Исходная модель не меняется; копию агент рассчитывает и проверяет `lira_slab_deflections` |
| `lira_slab_reinforcement` | Мозаики армирования AS1–AS4 плит по огибающей, которую подобрала ЛИРА (от отдельного РСН в ЛИРЕ 2024 недоступно), со шкалой, которую передаёт агент: `levels` — «ступени в см²/м», или `background` и `addons` — «фон + доборы» (диаметр и шаг). По умолчанию отчёт Word и PDF и DXF зон по плите: отдельный план на каждый слой арматуры, по два в ряд (слой на направление и полосу шкалы, контуры и штриховки, мм), у каждого элемента — требуемая арматура отдельным слоем (`AS1_VALUES`); PNG — с `formats` `["png", "dxf"]`. Ответ — наибольшая площадь и площади зон |

## Стержневые конструкции

Факты для РПЗ без вывода «годно / не годно»: по СП РК EN 1993-1-1 (п. 7.2.1, 7.2.2) и
национальному приложению (НП.2.21, НП.2.23) предельные прогибы и перемещения
устанавливаются для каждого проекта, их сравнивает инженер.

| Инструмент | Что делает |
|---|---|
| `lira_member_deflections` | Прогибы балок и смещения колонн стержневого каркаса (КЭ 1–10) по загружению или РСН. Соосные стержни подряд — один элемент конструкции; балка делится на пролёты опорами: закреплённые узлы, одноузловые опоры и сваи, узлы, от которых вниз идёт колонна, АЖТ и объединения перемещений с такими узлами, узлы элементов из `supported_by` (прогон на ригелях — укажите ригели). Части за крайними опорами — консоли. Прогиб f — наибольшее перемещение промежуточного узла поперёк стержня относительно прямой между опорами (осадка и крен опор не считаются прогибом), fz — его вертикальная часть со знаком ЛИРЫ; у пролёта из одного КЭ промежуточных узлов нет и прогиб не определяется (`blind_spans`, примечание). Колонна (отклонение от вертикали до 15°): горизонтальное смещение верха относительно низа u, H/u и худший участок между узлами примыкания других элементов. Ответ — 10 худших пролётов (наименьшее L/f) и колонн, итоги и примечания; с `output_dir` — `<модель>_members.xlsx` со всеми и `<модель>_members.docx` с таблицами для РПЗ; с `pictures=true` — PNG для приложений (А4, 200 dpi): схема по жёсткостям с опорами, деформированная схема (масштаб — наибольшее перемещение 5 % размера модели, узел подписан) и пролёты по цвету L/f с тремя худшими подписанными; `view`: `iso` (по умолчанию), `xz`, `yz`, `xy` |
| `lira_force_diagrams` | Эпюры усилий в стержнях каркаса (КЭ 1–10) для приложений РПЗ: по одной картинке PNG (А4, 200 dpi) на компоненту — `<модель>_<компонента>_<вид>.png` в `output_dir`. Значения — усилия ЛИРЫ в расчётных сечениях стержней по загружению (`load_case`) или РСН (`combination` и предельное состояние `limit_state`: `ultimate` по умолчанию, `ultimate_long`, `serviceability`, `serviceability_long`), в кН и кН·м, со знаком ЛИРЫ, без пересчёта. Расчётные сечения отложены равномерно по длине, первое — в начале стержня; между ними эпюра — прямая, поэтому при двух сечениях (начало и конец) пролётного значения не видно — ответ об этом предупреждает. Ординаты откладываются поперёк стержня в плоскости картинки: положительные — красные, вверх (у вертикального на картинке стержня — влево), отрицательные — синие, в другую сторону; масштаб один на картинку, подписаны наибольшее и наименьшее значения с номером элемента. `components` — из N, Qy, Qz, Mx, My, Mz (по умолчанию N, Qz, My, Mz); `elements` — номера, `selected`, `visible`; `view`: `iso` (по умолчанию), `xz`, `yz`, `xy` (стержни, видимые с торца, без эпюр — примечание). Ответ — наибольшее и наименьшее значение каждой компоненты с элементом и сечением, файлы, примечания |
| `lira_steel_check` | Проценты использования стальных сечений по проверке ЛИР-СТК из файла `.rez`, который ЛИРА пишет при расчёте в свою рабочую папку: `<модель>.rez` — вариант конструирования 1, `<модель>#1.rez` — вариант 2 и так далее (или `rez_path`). По каждому элементу назначенного сечения — 1ПС (`1LS`), 2ПС (`2LS`) и местная устойчивость (`LB`) строками, как их записала ЛИРА, без пересчёта и округления; `NR` и 1e20 — у ЛИРЫ нет результата. Сводка по жёсткостям (номер берётся из имени сечения «1.1.1. …», иначе по сечению): наибольшее значение и элемент, где оно. `over_100` — элементы, где процент больше 100: это факт, не вывод; `no_result` — элементы и показатели без результата ЛИРЫ (они не проверены, пустой `over_100` не значит, что всё проходит). Если `.rez` в разделе `[General]` называет другую модель — предупреждение. Фильтры `elements` (номера, `selected`, `visible`) и `stiffnesses`, сортировка `sort_by` и `top`; `export_path` — все строки и сводка в .xlsx или .csv. Предупреждает, если `.rez` старше файла модели |

## Данные для РПЗ и основания

| Инструмент | Что делает |
|---|---|
| `lira_rpz_facts` | Данные посчитанной модели для разделов 1.7 и 4 РПЗ: загружения (номер, имя, вид, γf и доля длительной из таблицы `DCL`), жёсткости с параметрами и числом элементов, состав каждого РСН — множитель каждого загружения. Коэффициент загружения в РСН не отдают ни API, ни `DCL`: он подбирается по перемещениям до 300 узлов (перемещения РСН — сумма перемещений загружений с этими множителями, в них уже 1/γf). `exact=false` — РСН не сводится к такой сумме (динамика, `dynamic_cases_left_out`), состав приближённый; или загружения двигают узлы пропорционально (`ambiguous_cases`, например вес кровли и снег на одних плитах) — их множители по отдельности не определены, состав не выдаётся, в ответе и в docx предупреждение. С `output_dir` — `<модель>_rpz_facts.docx` с таблицами и `<модель>_rpz_facts.json` — те же факты и SHA-256 файла модели для ЛИРА+ (черновой формат обмена, [решение 0006](decisions/0006-lira-plus-exchange.md)) |
| `lira_rpz_pictures` | Картинки приложений РПЗ так, как их рисует сама ЛИРА — раскладка как в образце РПЗ. Для каждой модели (`models`: `model`, `title`, `scheme_appendix`, `appendix`, `groups`) сервер сам переключает окно ЛИРЫ: режим результатов, РСН или загружения, пункт списка в строке состояния (номер РСН/загружения или огибающая MAXIMUM / MINIMUM / MAX ABS — пункт проверяется, не угадывается), мозаику, фрагмент группы элементов и проекцию, — и снимает окно. Схема модели — `scheme_views` (по умолчанию изометрия, XOY, XOZ) в приложение `scheme_appendix`. Группа (`stiffnesses`, `elements` или `whole_model`) по умолчанию даёт как у арки в образце РПЗ: N огибающая max и min, сталь 1ПС, сталь местная устойчивость, перемещения Z по худшему РСН; с `foundation=true` — Rz min, max, Rz и Z по худшему РСН. `pictures` — свой набор: `N:MAXIMUM`, `My:rsn5`, `Qz:case3`, `disp_Z:rsn` (РСН с наибольшим \|Z\| в узлах группы — в примечании). Сталь (ЛИР-СТК, % несущей способности, без пункта списка): поэлементно проверка назначенных сечений `steel_1LS`, `steel_2LS`, `steel_LB` (местная устойчивость), `steel_max` (огибающая трёх) и то же для подобранных сечений `steel_sel_1LS` … `steel_sel_max`; по расчётным сечениям СП `steel_sec_<проверка>` и `steel_sel_sec_<проверка>`, проверка — `normal`, `shear`, `reduced` (напряжения), `stab_Y1`, `stab_Z1`, `stab_2planes`, `slender_Y1`, `slender_Z1`, `slender_ratio`, `beam_stab`, `web`, `flange`, `deflection`, `ribs`, `lattice`; для них сервер ставит в ЛИРЕ «показывать проверку / подбор» и «для всех типов элементов», и они так и остаются. Файлы PNG нумеруются внутри приложения (`Ж01 Усилия в арке - N огибающая max.png`) в `output_dir`, рядом `pictures.json` — что на каждой картинке. Каждая картинка результатов проверяется: если на ней нет цветов мозаики (ЛИРА её скрыла — повторная команда той же мозаики в ЛИРЕ её выключает), команда повторяется до трёх раз; не вышло — картинка сохраняется с примечанием «Мозаики на картинке не видно…». Настройки отображения ЛИРЫ (масштаб, подписи, нагрузки) остаются пользовательскими. Нужна запущенная ЛИРА с окном |
| `lira_kz_loads` | Снег и ветер по нормам РК для раздела 3 РПЗ, нормативные значения без коэффициента надёжности; формулы и округления как в «ЛИРА+ Записка» (сверено число в число). Модель не нужна. Город из справочника (9 городов) или районы вручную: ветер по НТП РК прил. Ж, снег по картам 4, 5, 6. Расчёты: `snow_duopitch` (5.3.3; чрезвычайный снег при пролёте ≥ 18 м по НТП РК 3.4.1), `snow_multispan` (5.3.4, прил. B.2), `snow_step` (мешок у перепада, 5.3.6 и прил. B.3), `wind_building` (гл. 4 с zmin, табл. 7.1 и 7.2), `wind_vault` (сводчатое покрытие, 7.2.8, рис. 7.11). Ответ — значения, строки сводки (кг/м²) и ход расчёта по-русски; с `output_dir` — `<name>_нагрузки.docx` |
| `lira_model_check` | Контроль модели перед РПЗ, ничего не меняет: результаты есть и от этой версии модели, модель не сохранялась после расчёта, у всех элементов есть жёсткость (сваи КЭ 57 не в счёт), нет узлов вне элементов и совпадающих узлов (ближе 1 мм), РСН заданы и каждое загружение входит хотя бы в одно (по подобранному составу РСН). По каждой проверке — `ok`, формулировка по-русски, число и до 20 найденных номеров |
| `lira_footing_pressure` | Давление под прямоугольными фундаментами по СП РК 5.01-102-2013: среднее p ≤ R (п. 4.6.1), краевое ≤ 1,2R и угловое ≤ 1,5R (п. 4.6.19), e ≤ l/6 и pmin ≥ 0, pmin/pmax ≥ 0,25 для крановых зданий от 75 т, открытых крановых эстакад свыше 15 т, башен (`trapezoid`) и всегда при R ≤ 150 кПа (п. 4.6.20); p = N/A + γmt·d, краевые по линейному закону (п. 4.6.21). Нагрузки — «нагрузки на фрагмент» ЛИРЫ (фрагмент с узлами фундаментов задаётся в ЛИРЕ до расчёта) по загружению или РСН (множители РСН × нагрузки загружений). Фундамент: `nodes`, `l`, `b`, `d` (м), `R` (кПа, задаёт инженер), `gamma_mt` (по умолчанию 20), `trapezoid`, `name`. `compression_rz_sign` (+1 или −1) задаёт проверенный знак RZ при сжатии. Без него давление не определяется. Отрыв с учётом веса отмечается отдельно. `center: [X,Y]` в метрах, по умолчанию среднее координат узлов. `h_node` в метрах над подошвой, по решению владельца по умолчанию 0. Моменты переносятся к центру подошвы. Требуются глобальные оси и нулевой поворот группы фрагмента. При двухосном выходе за ядро вычисляется численное распределение без растяжения с проверкой равновесия |

## Скрипт агента

| Инструмент | Что делает |
|---|---|
| `lira_run_script` | Выполнить Python-код агента внутри сервера с объектами ЛИРЫ — для всего, что не покрыто инструментами. Перед этим сервер делает копию модели |

`lira_run_script` даёт агенту полный доступ к ЛИРЕ, Python и файлам компьютера. Он
включён по умолчанию; флаг `--no-scripts` в команде запуска убирает его — см.
[Эксплуатацию](operations.md).
