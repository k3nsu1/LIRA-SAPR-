## Technical debt

Долг проверок этапов 5 и 6 закрыт 2026-11-04 ([история](history/stage-6.md)).

Ревью К2 (2026-11-10), низкий приоритет:

- Интеграция формата обмена с ЛИРА+ ждёт решения владельца по Н6.
- `.rez` ищется только по имени модели в общей рабочей папке ЛИРЫ: модель с тем же именем из другой папки
  пишет тот же файл, и это не обнаруживается (сказано в описании инструмента) — `services/steel.py`
- константа тс → кН в двух местах (`services/rpz.py`, `services/results.py`)

Принято владельцем как известные ограничения (2026-10-30):

- правка нагрузок даёт черновик с отчётом вместо замены модели, если пересборка не
  совпала с исходной: нормы сочетаний не по умолчанию (не СП 20.13330, например СНиП),
  изменённые вручную γf в РСН без таблицы РСУ, группы взаимоисключения РСН (`DCL`,
  столбец 6), которые импорт ставит по РСУ (принято 2026-11-02), физически нелинейная
  арматура, которую теряет импорт ЛИРЫ (принято 2026-10-31), вопрос «Монтаж → ИН2» у
  моделей вроде примера 16; возможные пути — API 2025+ — `services/loads.py`
- в живых тестах faulthandler печатает «Windows fatal exception 0x80010108 /
  0x800401fd» при освобождении ссылок на документы, которые ЛИРА закрыла после расчёта;
  исключения обработаны, тесты проходят — tests/live
- плиты, принято владельцем 2026-11-07: нелинейные аналоги одноузловых КЭ 2xx остаются опорами, их запись не проверена;
  локальные оси узла не учитываются, `Rz` читается как глобальный Z; собственная жёсткость сваи КЭ 57 не читается; свая
  под стержнем считается колонной и плита идёт по прогибу (если появится такой проект, вернуться к списку плит «по
  осадке» в параметре); на нарочно шумном поле поиск пар для Δs/L квадратичный (6 106 точек — 180 с под замером памяти);
  плита с пружинами во всех узлах внутри одного АЖТ на колонне считается по прогибу со скрытыми значками опор —
  `postprocessing/mesh.py`, `postprocessing/settlement.py`, `services/slabs.py`
- ЛИРА однажды не закрыла временный документ импорта, и все следующие вызовы падали, пока владелец не закрыл документы
  вручную; причина не выяснена, ответ теперь советует закрыть документы (принято владельцем 2026-11-07). Если сбои
  станут частыми, разобраться отдельно — `adapters/com_adapter.py`
- нарочно написанный скрипт агента (`try`/`except BaseException: pass` в одной строке,
  `finally: continue`) обходит предел времени; остальные вызовы отказывают и советуют
  перезапустить MCP-сервер — `services/scripts.py`
- выгрузка результатов пишет по любому абсолютному пути (в т.ч. сетевому) и заменяет
  существующий файл, ответ сообщает об этом; ограничивать путь бессмысленно, пока есть
  скрипт агента — `services/results.py`
