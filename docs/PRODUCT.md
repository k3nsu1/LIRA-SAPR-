# Lira-Sapr-MCP

Status: approved 2026-10-27

## Коротко

MCP-сервер, через который любой ИИ-агент (Claude, Codex, Hermes и другие) управляет
ЛИРА-САПР на компьютере инженера: создаёт и редактирует расчётные модели, запускает расчёт
и получает результаты.

## Для кого

- **Сейчас:** владелец проекта — инженер-конструктор; сервер работает на его компьютере с
  установленной ЛИРОЙ, на нескольких машинах с разными версиями ЛИРЫ.
- **После публикации на GitHub:** другие инженеры, которые ставят сервер на свои
  компьютеры со своей ЛИРОЙ.
- **В будущем (не v1):** офисный сервер, к которому по сети подключаются несколько
  пользователей.

## Какую проблему решает

Сегодня работа с ЛИРОЙ — ручные операции в интерфейсе: построение схемы, правка таблиц,
перебор вариантов, поиск экстремумов в результатах. Автоматизировать это можно только
программированием на COM API, а готового MCP-сервера для ЛИРЫ нет. Сервер даёт агенту
полный набор действий с ЛИРОЙ: инженер формулирует задачу словами, агент выполняет её
в ЛИРЕ и возвращает итог.

## Как это работает для пользователя

Основной сценарий:

1. Инженер подключает сервер к своему агенту (одна запись в настройках MCP-клиента).
2. Сервер находит установленные версии ЛИРЫ и сообщает агенту, что доступно.
3. Инженер пишет задачу, например: «открой модель D:\Проекты\Рама.lir, увеличь сечение
   ригелей до 40×60, пересчитай и сравни максимальные прогибы с прошлым вариантом».
4. Агент открывает модель, получает сводку, правит таблицы ввода. Перед первой правкой
   сервер сам сохраняет резервную копию модели.
5. Агент запускает расчёт, сервер ждёт его окончания и сообщает, успешен ли расчёт и
   какие были ошибки.
6. Агент запрашивает результаты: сервер отдаёт компактный ответ (выборка, экстремумы),
   а полные таблицы — файлом CSV/Excel.
7. Инженер видит изменения в открытой ЛИРЕ и получает от агента отчёт.

Другие сценарии v1:

- **Анализ готовой модели:** открыть, рассчитать, найти экстремумы перемещений и усилий,
  сделать сводку.
- **Создание модели с нуля:** узлы, элементы, жёсткости, связи, загружения и нагрузки
  по текстовому описанию.
- **Параметрические исследования:** серия вариантов (сечения, жёсткости, шаг), расчёт
  каждого в отдельной копии, сравнение результатов.
- **Проверка и правка модели:** поиск элементов без жёсткости, свободных и совпадающих
  узлов; массовая замена параметров.

## Особые случаи

- **ЛИРА не установлена или версия ниже 2024 R2:** сервер запускается, но сообщает агенту
  понятную ошибку и список найденных версий.
- **Нет лицензии (ключа):** ошибка с текстом «ЛИРА не запустилась: проверьте ключ защиты».
- **ЛИРА показала диалоговое окно** и ждёт пользователя: сервер не зависает навсегда —
  по тайм-ауту сообщает агенту, что ЛИРА ждёт действия в интерфейсе.
- **Ошибка в данных таблицы:** агент получает список ошибок ЛИРЫ по строкам и столбцам,
  модель не меняется.
- **Долгий расчёт** (минуты и часы): расчёт идёт в фоне; агент узнаёт статус отдельным
  запросом, может остановить расчёт.
- **Расчёт завершился ошибкой:** агент получает протокол расчёта.
- **Два агента одновременно:** сервер выполняет команды к ЛИРЕ по очереди.
- **Модель открыта инженером и не сохранена:** сервер не закрывает её молча и не
  перезаписывает несохранённые изменения.
- **Порча модели агентом:** откат из резервной копии.
- **Правка нагрузок не прошла сверку** (пересобранная модель отличается от исходной:
  например, нормы сочетаний не по умолчанию или данные нелинейного расчёта, которые
  ЛИРА теряет): исходная модель не
  меняется, а пересобранная с новыми нагрузками всегда сохраняется рядом как черновик
  `<имя>_кор_нагр_error.lir` (если такой есть — с номером: `_2`, `_3`, …) вместе с
  отчётом `<имя>_кор_нагр_error.txt` о том, что не совпало. Нужен ли черновик, решает
  пользователь, а не агент (решение владельца, 2026-10-31).

## Первая версия включает

- **Файлы и расчёт:** открыть, создать, импортировать, сохранить, закрыть модель;
  запустить расчёт, дождаться его, остановить, удалить результаты; архивы ЛИРЫ.
- **Редактирование модели:** все таблицы ввода, которые даёт API (узлы, элементы,
  жёсткости, связи, шарниры, жёсткие вставки, C1/C2, локальные оси, монтаж, загружения,
  РСН, массы, оси, отметки, конструктивные блоки, материалы); выделение; собственный вес;
  модель грунта; нагрузки на узлы и элементы — через текстовый формат ЛИРЫ (см. «Решённые
  вопросы»).
- **Два уровня инструментов:** универсальный доступ к любой таблице ввода и удобные
  операции высокого уровня («добавить узлы», «назначить жёсткость» и т.п.).
- **Сводка модели:** количество узлов и элементов, типы КЭ, жёсткости, загружения,
  наличие результатов.
- **Результаты:** перемещения, усилия и напряжения, РСУ, РСН, периоды колебаний,
  подобранная арматура, нагрузки на фрагмент, продавливание. Сервер умеет универсальные
  операции над результатами: выбрать элементы, узлы, загружения и компоненты; отсортировать;
  взять N наибольших; найти минимум и максимум; построить огибающую; отобрать по порогу.
  Полные таблицы выгружаются в CSV/Excel.
- **Справочник форматов таблиц** для агента: колонки, единицы, коды типов КЭ.
- **Картинка модели** в PNG для агентов, которые видят изображения.
- **Поддержка версий:** ЛИРА-САПР 2024 R2 и все более новые (2025, 2026, …). Общий набор
  инструментов работает во всех версиях; возможности, которые появились в новых версиях API,
  сервер включает автоматически, когда находит такую версию.
- **Автоопределение версий ЛИРЫ** и доступных возможностей.
- **Резервная копия** модели перед первой правкой или сохранением в сессии.
- **Выполнение скрипта:** агент запускает свой Python-код с доступом к объектам ЛИРЫ —
  для всего, что не покрыто отдельными инструментами. Включено по умолчанию; пользователь
  может выключить его флагом `--no-scripts` в команде запуска (решение владельца,
  2026-10-28).
- Документация для пользователей и публикация на GitHub.

## Не в первой версии

- САПФИР (архитектурная модель) и передача из САПФИР в расчётную схему — запланировано
  во второй версии (этап 8).
- Сетевой многопользовательский сервер (архитектура должна его допускать).
- Версии ЛИРЫ ниже 2024 R2.
- Готовые инженерные проверки по нормам (прогибы по СП и т.п.) — во второй версии
  только прогибы плит (этап 6); остальное агент делает сам из результатов.
- Формирование отчётов в Документаторе ЛИРЫ.

## Вторая версия: задачи инженера

Утверждено владельцем 2026-11-03 после разбора 11 сценариев. Устройство — решения
[0003](decisions/0003-postprocessing.md) (постобработка) и
[0004](decisions/0004-sapfir.md) (САПФИР), план — этапы 5–8 в [задачах](TASKS.md).
Сервер по-прежнему работает с ЛИРОЙ 2024 R2; возможности API 2025/2026 (таблицы
нагрузок, материалов, РСУ, вариантов конструирования) подключаются в их адаптерах,
когда такая версия будет проверена.

**Указание элементов (этап 5).** Нагрузки, жёсткости, материалы конструирования и
результаты агент применяет к элементам, которые инженер указал одним из трёх способов:

- выделил мышкой в окне ЛИРЫ («возьми выделенные»);
- отфрагментировал в ЛИРЕ («работай с видимыми»);
- описал словами по признакам: отметка, тип КЭ, жёсткость, материал, конструктивный блок
  («плиты на отметке +15,000», «стены с жёсткостью 7»).

Агент показывает, что нашёл (число элементов), до правки. Новые жёсткости — только
копией существующей с изменёнными параметрами. Материалы конструирования инженер
создаёт в окне ЛИРЫ (в API 2024 их создать нельзя), агент их назначает. Усилия
пластин — в центре элемента; выгрузка в Excel и CSV для таблиц инженера и скриптов.

**Плиты: прогибы, изополя, мозаики, отчёты (этап 6).**

- Прогиб плиты оценивается по линиям между опорами, как по линии взгляда: берутся все пары
  точек опор (колонны, пилоны, стены), между которыми есть прямая видимость, то есть линия не
  выходит за край плиты и отверстия, не проходит через другую опору и не пересекает стену.
  Прогиб смотрится только в точках самой линии: перемещение прямой между её концами минус
  перемещение точки; пролёт — длина линии, предел — по СП 20 для этой длины. Консоль: вылет — по
  кратчайшему расстоянию от свободного края до опоры, прогиб — на конце этой линии, пролёт равен
  двойному вылету.
- Точка наибольшего прогиба панели обычно не лежит ни на одной такой линии: по другим линиям
  она не оценивается, а показывается на изополе с подписью перемещения в ней, в каждой панели.
- Трещины учитываются понижающим коэффициентом к модулю упругости плит (kE) в копии
  модели; коэффициент задаёт инженер.
- Изополя прогиба относительно опор и отношения к допустимому; в узле — наибольший прогиб из
  проходящих рядом линий, шкала прогиба своя на каждую плиту; «плита» — связная часть пластин
  на одной отметке. На картинке плита показана одна и крупно, рядом — маленькая схема, где она
  находится среди остальных плит. Отмечены три самых опасных участка, а если участков с
  превышением предела больше трёх — все такие участки: линия и её худшая точка с номером, числа
  по каждому номеру — в тексте.
- Отчёт Word/PDF — основной результат: сводная таблица и по каждой плите изополя,
  наибольший прогиб с подробным пояснением в числах (перемещения опор и точки, пролёт,
  как получен предельный прогиб, отношение и вывод) и те же числа по остальным показанным
  участкам; каждая картинка — на отдельном листе, повёрнутом так, чтобы плита вышла крупнее.
  Отдельные PNG — только по просьбе инженера.
- Знак прогиба как в ЛИРЕ: минус — плита ниже прямой между опорами. Изополя заполняют всю плиту по одному
  правилу: перемещение узла минус поверхность через опоры; при опорах в нуле они равны перемещениям ЛИРЫ.
- Отчёт по прогибам и отчёт по армированию можно сделать и по выбранной плите: номерами элементов,
  выделением в окне ЛИРЫ, фрагментом или поиском. Номер плиты — как в полной модели, отчёт по всей
  модели не заменяется; о выборе части плиты отчёт предупреждает.
- Плита на упругих элементах, то есть фундамент или плита на сваях: одноузловые упругие элементы любого типа
  составляют больше половины её опор, под всей плитой или под отдельными точками, либо коэффициенты постели заданы
  больше чем у половины её элементов. Прогиб и СП 20 не применяются. Знак осадки как в ЛИРЕ: минус — вниз, с
  пределом сравнивается абсолютная величина. Показаны изополя осадки и
  наибольшая относительная разность осадок |s₁ − s₂| / L по СП 22 между вертикальными конструкциями,
  опирающимися на плиту: колонна на АЖТ — одна точка в центре, стена или пилон — одна конструкция,
  внутри неё только точки дальше 3 м друг от друга. Пока предел не превышен — одна линия с
  наибольшим значением; при превышении — все участки с превышением. Зоны, где осадка больше
  предельной, выделены. Пределы задаёт агент, по умолчанию 0,003 и 150 мм.
- По просьбе инженера — DXF прогибов и осадок: мозаика по элементам на шкале изополя плиты, зоны отдельными слоями,
  у каждого элемента подпись значения (среднее по его узлам) отдельным слоем, как у мозаик армирования.
- Мозаики армирования AS1–AS4 по каждой плите, по огибающей, которую подобрала ЛИРА
  (армирование от отдельного РСН в ЛИРЕ 2024 недоступно). Шкала «фон + доборы»
  (фоновое армирование и варианты добора диаметром и шагом) или ступени в см²/м — её
  называет инженер, агент передаёт серверу. По умолчанию — отчёт Word/PDF и DXF с зонами
  доборов для чертежа: в файле плиты отдельный план на каждый слой арматуры и у каждого
  элемента подпись требуемой арматуры отдельным слоем, чтобы её легко выключить; PNG — по
  просьбе.

**Пробы на живой ЛИРЕ (этап 7).** Создание новых РСН записью таблицы `DCL`; задание
фрагмента через API для нагрузок на фрагмент; шаблон `.lir` с материалами
конструирования для новых моделей. По каждой пробе — инструмент, если она удалась, или
записанное ограничение.

**САПФИР (этап 8), делается последним.**

- Модель этажа из DXF: слои с контуром плиты, отверстиями, стенами, пилонами,
  колоннами, площадными и линейными нагрузками (величина — в имени слоя) и материалы →
  стены, плиты и колонны в САПФИРе → сетка и расчётная схема → ЛИРА → расчёт и
  результаты. Стены и колонны на высоту этажа с жёстким защемлением внизу; пилоны (все
  длиннее трёх толщин) — оболочками. Нагрузки на торцы стен — «нагрузками на фрагмент»
  ЛИРЫ. РСУ новой модели задаёт агент.
- Аналитическая модель из Revit → САПФИР → расчётная схема ЛИРЫ.
- Отверстия в плите существующей модели — тем же путём через САПФИР.
- Сначала проба: строит ли САПФИР модель и передаёт ли её в ЛИРУ через API без окон.
  Если нет — свой генератор сетки (gmsh) для DXF; Revit и отверстия решаются заново.

## Как поймём, что работает

1. Агент создаёт с нуля П-образную раму 6×3 м из трёх стержней с заданным сечением,
   защемлением опор и равномерной нагрузкой на ригель, запускает расчёт и сообщает
   максимальный изгибающий момент в ригеле; число совпадает с тем, что инженер видит в ЛИРЕ.
2. Агент открывает готовую модель, выдаёт сводку (число узлов, элементов, загружений), и
   она совпадает с данными в интерфейсе ЛИРЫ.
3. Агент меняет жёсткость группы элементов, пересчитывает модель и сравнивает максимальные
   перемещения до и после; рядом с моделью лежит резервная копия исходного файла.
4. Для модели с 10 000+ элементов агент получает 10 наибольших усилий за один запрос
   (ответ — десятки строк, не мегабайты), а полную таблицу — файлом CSV.
5. Если ЛИРА показала модальное окно, агент получает сообщение об этом в пределах
   тайм-аута, а не ждёт бесконечно.
6. Тот же сервер без изменений кода работает на другом компьютере с ЛИРОЙ 2024 R2.
   Пока не проверено: другого компьютера с ЛИРОЙ нет; этап 4 закрыт без этой проверки
   (решение владельца, 2026-10-29). Установка с GitHub в чистую папку с пустым кэшем
   проверена на компьютере разработки.

Вторая версия:

7. Инженер выделяет в окне ЛИРЫ группу колонн; агент по просьбе «увеличь выделенные
   колонны до 50×50» создаёт жёсткость копией, назначает её именно этим колоннам и
   показывает их число до правки. Так же — для фрагмента и для поиска словами.
8. Прогиб относительно опор на простых плитах с известным ответом (балочная плита на двух
   стенах, плита на четырёх колоннах, консоль) совпадает с ручным расчётом; на плите
   многоэтажной модели он меньше абсолютного перемещения на величину укорочения опор.
9. По модели владельца агент выдаёт отчёт Word/PDF по прогибам: сводная таблица и по
   каждой плите изополя со своей шкалой, наибольший прогиб, пролёт и вывод.
10. Мозаики армирования плиты в отчёте и DXF совпадают по зонам с мозаикой ЛИРЫ при той
    же шкале; DXF открывается в программе чертежей инженера.
11. Этап 8: из DXF этажа по договорённым слоям получается рассчитанная модель ЛИРЫ, а
    из аналитической модели Revit — расчётная схема; или записан понятный отказ пробы и
    принятый владельцем запасной путь.

## Ограничения

- Windows; установленная ЛИРА-САПР 2024 R2 или новее с действующей лицензией (ключ Guardant).
- ЛИРА работает с графическим интерфейсом на том же компьютере, что и сервер.

## Допущения

- Поддержка версии считается подтверждённой, только когда сервер проверен на реальной
  установке этой версии; до проверки версия помечается как «должна работать».
- Запуск — как локальный процесс, который MCP-клиент стартует сам.
- Резервные копии лежат в папке рядом с моделью; сервер их не удаляет.
- Тайм-аут ожидания ответа ЛИРЫ по умолчанию — 60 секунд (кроме расчёта).
- Операции над результатами — универсальные (выборка, сортировка, экстремумы, огибающие),
  а не заготовленные под конкретные инженерные задачи. Исключение второй версии —
  прогибы, изополя и мозаики плит: их правила согласованы с владельцем и проверены
  тестами, чтобы каждое задание считалось одинаково.
- «Выполнение скрипта» работает и у других пользователей сразу после установки — README
  предупреждает, что агент получает полный доступ к ЛИРЕ, Python и файлам компьютера, и
  показывает, как выключить скрипты.

## Решённые вопросы

- **Нагрузки на узлы и элементы** (в API 2024 R2 нет таблицы ввода нагрузок) — решено
  на этапе 1 (2026-10-27): новая модель с нагрузками строится импортом текстового
  формата ЛИРЫ (`lira_import_text_model`), нагрузки существующей модели меняются её
  пересборкой через текстовый формат с проверкой всех таблиц (`lira_set_loads`).
  Ограничение: модели по нормам сочетаний не по умолчанию так не правятся (принято
  владельцем 2026-10-29). У моделей со стадиями монтажа с 2026-10-31 стадии и
  порядок загружений в истории монтажа при пересборке сохраняются; если пересборка
  теряет другие данные (например, изменённые вручную коэффициенты РСН или арматуру для
  нелинейного расчёта), получается черновик с отчётом. В ЛИРЕ 2025 появилась таблица ввода
  «Нагрузки» — её можно будет использовать, когда версия будет проверена.
- **РСУ** (нет отдельной таблицы ввода в API 2024 R2) — решено на этапе 1 (2026-10-27):
  виды загружений и коэффициенты РСУ хранит документ 8 текстового формата, поэтому РСУ
  задаются в тексте модели и сохраняются при пересборке. Результаты РСУ сервер читает
  (`lira_design_forces`). В ЛИРЕ 2026 появилась таблица ввода РСУ.

## Словарь

- **MCP (Model Context Protocol)** — стандарт, по которому ИИ-агент подключается к
  внешним инструментам.
- **MCP-сервер** — программа, которая предоставляет агенту набор инструментов.
- **Инструмент MCP** — одна операция, которую агент вызывает с параметрами.
- **COM API** — механизм Windows, через который внешняя программа управляет ЛИРОЙ.
- **Таблица ввода** — табличное представление исходных данных модели в ЛИРЕ.
- **РСУ / РСН** — расчётные сочетания усилий / расчётные сочетания нагрузок.
- **Огибающая** — максимальные и минимальные значения по множеству загружений.
