# lira-sapr-mcp

MCP server that lets AI agents (Claude, Codex and other MCP clients) drive LIRA-SAPR /
LIRA-FEM 2024 R2 and newer on Windows through its COM API: create and edit models, run
the analysis, read results. Documentation is in Russian.

MCP-сервер, через который ИИ-агент управляет ЛИРА-САПР на компьютере инженера: создаёт и
правит расчётные модели, запускает расчёт и получает результаты — компактно, а полные
таблицы файлом CSV/Excel.

## Что умеет

- **Модели:** открыть, создать, импортировать из текстового формата ЛИРЫ, сохранить,
  закрыть; сводка (узлы, элементы, типы КЭ, жёсткости, загружения, есть ли результаты);
  картинка модели в PNG.
- **Правка:** любая таблица ввода ЛИРЫ; нагрузки; операции высокого уровня — добавить
  узлы и элементы, назначить или создать жёсткость, связи, собственный вес.
- **Расчёт:** запуск с ожиданием, статус, остановка, протокол, удаление результатов.
- **Результаты:** перемещения, усилия и напряжения всех типов КЭ, РСН, РСУ, периоды и
  модальные массы, подобранная арматура, нагрузки на фрагмент и продавливание. Сервер
  отдаёт экстремумы и N наибольших строк, строит огибающие, отбирает по порогу и
  выгружает полные таблицы в CSV или Excel.
- **Надёжность:** резервная копия модели перед первой правкой и откат из неё; агент
  видит модальные окна ЛИРЫ и может ответить на них; честный ответ, если ЛИРА не уложилась
  в тайм-аут.
- **Скрипт агента:** для всего остального агент выполняет свой Python-код с объектами
  ЛИРЫ.

Все 52 инструмента с описанием — в [docs/tools.md](docs/tools.md).

## Что нужно

- Windows и ЛИРА-САПР 2024 R2 или новее с действующей лицензией. ЛИРА работает с
  окном на том же компьютере; сервер запускает её сам, если она не запущена.
- [uv](https://docs.astral.sh/uv/getting-started/installation/) — он сам поставит
  нужный Python и библиотеки. Установка uv в PowerShell:

  ```powershell
  powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
  ```

## Подключение к агенту

Сервер ставить отдельно не нужно: агент запускает его командой `uvx`, которая при
первом запуске скачивает сервер с GitHub и собирает его в отдельном окружении (около
минуты), а потом берёт из кэша.

Команда запуска сервера:

```bash
uvx --from git+https://github.com/k3nsu1/LIRA-SAPR- lira-sapr-mcp
```

**Claude Code** — в терминале:

```bash
claude mcp add lira-sapr -- uvx --from git+https://github.com/k3nsu1/LIRA-SAPR- lira-sapr-mcp
```

**Codex** — в файле `%USERPROFILE%\.codex\config.toml`:

```toml
[mcp_servers.lira-sapr]
command = "uvx"
args = ["--from", "git+https://github.com/k3nsu1/LIRA-SAPR-", "lira-sapr-mcp"]
```

**Claude Desktop, Cursor и другие клиенты с JSON-настройкой** (в Claude Desktop это
файл `claude_desktop_config.json`: Settings → Developer → Edit Config):

```json
{
  "mcpServers": {
    "lira-sapr": {
      "command": "uvx",
      "args": ["--from", "git+https://github.com/k3nsu1/LIRA-SAPR-", "lira-sapr-mcp"]
    }
  }
}
```

После настройки перезапустите агента и попросите его вызвать `lira_status`: он покажет
найденные версии ЛИРЫ и какая используется.

**Обновление.** `uvx` держит собранный сервер в кэше. Чтобы взять новую версию с GitHub,
выполните один раз и перезапустите агента:

```bash
uvx --refresh --from git+https://github.com/k3nsu1/LIRA-SAPR- lira-sapr-mcp --version
```

**Без доступа к GitHub.** Скачайте папку проекта и укажите её вместо адреса:
`uvx --from C:\path\to\lira-sapr-mcp lira-sapr-mcp`.

Настройки сервера (версия ЛИРЫ, тайм-ауты), журнал и решение проблем —
в [docs/operations.md](docs/operations.md).

## Важно знать

- **Скрипт агента получает полный доступ** к ЛИРЕ, файлам и Python на вашем компьютере
  (`lira_run_script`). Он включён по умолчанию: через него агент делает то, чего нет в
  остальных инструментах. Подключайте сервер только к агенту, которому доверяете, и
  следите за тем, что он запускает. Чтобы выключить скрипты, добавьте флаг
  `--no-scripts` в конец команды запуска — например, в Codex
  `args = ["--from", "git+https://github.com/k3nsu1/LIRA-SAPR-", "lira-sapr-mcp", "--no-scripts"]`.
  Скрипт останавливается по пределу времени (по умолчанию 120 с); нарочно написанный
  скрипт может этот предел обойти. Тогда остальные вызовы отвечают, что ЛИРА занята, и
  советуют перезапустить MCP-сервер: перезапуск останавливает скрипт, ЛИРА с моделями
  продолжает работать.
- Выгрузка результатов в CSV или Excel пишет по любому пути, который укажет агент, и
  заменяет существующий файл — ответ сообщает об этом.
- Перед первой правкой или перезаписью модели сервер кладёт её копию в папку
  `lira-mcp-backups` рядом с моделью и никогда не удаляет копии.
- **Нагрузки** в API ЛИРЫ задать нельзя, поэтому сервер меняет их, пересобирая модель
  через текстовый формат, и сверяет результат с оригиналом. Модели с нормами сочетаний
  ЛИРЫ по умолчанию (СП 20.13330) правятся полностью. У моделей со стадиями монтажа
  стадии и порядок загружений в истории монтажа сохраняются: линейная модель с монтажом
  правится полностью. Модели с физически нелинейной арматурой (кроме самой простой)
  уходят в черновик — импорт текста ЛИРЫ эту арматуру теряет. В черновик уходят и
  модели, у которых группы взаимоисключения РСН (столбец 6 таблицы `DCL`) не совпадают
  с группами РСУ: импорт ставит их по РСУ, и исправить их можно только вручную. Сверяются таблицы ввода,
  нагрузки и полный текст модели. Если что-то не совпало (например, нормы СНиП
  2.01.07-85\* или данные нелинейного расчёта, которые ЛИРА теряет), исходную
  модель сервер не меняет, а пересобранную с новыми нагрузками сохраняет рядом
  черновиком `<имя>_кор_нагр_error.lir` (если такой есть — с номером `_2`, `_3`, …) и
  кладёт к нему отчёт `<имя>_кор_нагр_error.txt`: что не совпало с исходной моделью
  (например, «Длительное(Д) -> Постоянное ( P)»). Нужен ли черновик, решаете вы: его
  можно поправить в окне ЛИРЫ или удалить. Не рассчитывайте черновик, пока не исправите
  всё, что перечислено в отчёте. Перед каждой правкой нагрузок сервер делает свежую
  резервную копию. Неупакованную схему (удалённые узлы и элементы ещё занимают номера)
  он не правит, пока вы не согласитесь её упаковать: упаковываются только удалённые
  узлы и элементы, номера остальных меняются, поэтому после упаковки агент заново
  читает нагрузки и задаёт их в новой нумерации. На вопрос модели, связанной с моделью
  грунта, «пересчитать C1/C2 и сваи?» сервер отвечает без пересчёта. Большая модель
  (230 тыс. узлов) правится около 20 минут.
- ЛИРА хранит результаты расчёта по имени модели: одноимённые модели из разных папок
  делят результаты. Сервер предупреждает агента, когда результаты принадлежат
  одноимённой модели, которую он рассчитал последней, или когда модель сохранена после
  расчёта и результаты могли устареть. Для этого после своего расчёта он кладёт в
  рабочую папку ЛИРЫ файл-метку `<имя модели>.lira-mcp.json`.
- Проверено на ЛИРА-САПР 2024 R2.3. Версии 2025 и 2026 поддерживаются тем же кодом,
  но пока не проверены. Если у вас 2025 или 2026, пришлите отчёт
  `uvx --from git+https://github.com/k3nsu1/LIRA-SAPR- lira-sapr-mcp --diagnose`
  (ЛИРУ он не запускает; отчёт появится в текущей папке; перед отправкой посмотрите
  его — там пути папок).

## Для разработчиков

```bash
uv sync
uv run pytest
```

Живые тесты на ЛИРЕ — `uv run pytest -m lira`. Как устроен сервер, какие решения
приняты и что проверено — сайт документации в `docs/`
(`uv run zensical serve -a localhost:8010`).
